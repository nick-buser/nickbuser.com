## Hypothesis

The 40 seconds looked like kernel compilation repeated on every pod start,
because Triton's and FlashInfer's caches lived in the container's temporary home
directory.

## Change

Both caches moved to the persistent volume.

## Result

Both caches were written and read on later runs, with no change in the start or
the first request. The vLLM log showed the engine idle for about 40 seconds
before it ran the warm-up request in about 5. A neighbouring pod on the same
image held a 6.5 MB cache from the CUDA driver itself, also in a temporary
directory.

## Decision

The hypothesis is out, and so is the layer it named. The time was being spent
below the frameworks, and the driver's cache was the next lead.
