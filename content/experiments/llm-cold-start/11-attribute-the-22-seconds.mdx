## Problem

With the engine fast, the 22 seconds of Python before it was the largest phase
left.

## Change

An import-time profile captured inside the real image, and a debug-log timeline.

## Result

The API server spends 13.75 seconds importing, led by torch (3.8 seconds) and
transformers (2.4).
The engine process spends another 5.3, because vLLM's command line starts it
with `spawn` and it imports everything again. LoRA support and the tracing
exporter cost nothing measurable, and running the engine in-process isn't
supported by the async server. Forking the engine process cut 5.7 seconds with
decode unchanged.

</Figure>

## Decision

Forking is about 14% of the start, under the 20% rule, so it was reported rather
than adopted. Step 15 picks it up.
